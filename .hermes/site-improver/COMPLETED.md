## 2026-07-01 — PR #41 (updated with T-11)
- **T-11** — Consultation form funnel tracking (`form_view` / `form_start` / `form_field_complete`). Fresh audit (2026-07-01) found that `components/forms/consultation-form.tsx` — the highest-intent conversion surface on the site, used on `/contact-us/`, `/hyperbaric-therapy/`, and all six `/condition/[slug]/` pages — only fired `form_submit` on success (T-02, 2026-05-29). Every other step in the conversion journey was invisible to GA4: GA could see "user submitted" but not "user saw the form" or "user started filling it out" or "which fields they completed before submitting". This was the most important funnel on a medical-practice site (the form is the only path to a lead), and the missing upstream events made conversion-rate optimization impossible — the team could measure the bottom of the funnel but not where users dropped off in the form itself.
- Three new dataLayer events close the funnel, all reusing the existing `trackEvent()` helper from `lib/analytics/track.ts` (the same one T-02 uses for `form_submit` and T-05 uses for `scroll_depth`):
  - **`form_view`** — fires once when the form scrolls into view, via an `IntersectionObserver` with `threshold: 0.1`. Captures the top of the funnel ("user saw the form"). Falls back to firing on mount if `IntersectionObserver` is unavailable. The observer is disconnected after the first hit so each page-view fires the event at most once.
  - **`form_start`** — fires once on the first `focusin` event inside the form. Captures mid-funnel engagement ("user started filling it out"). Listening on the form's `focusin` (which bubbles) means a single form-level handler covers all 5 fields, with no per-field wiring and no risk of double-firing from rapid tabbing.
  - **`form_field_complete`** — fires once per tracked field, on `blur` (in the capture phase so it fires before any per-field handler can stop propagation), when the field has a non-empty trimmed value. Captures per-field drop-off: GA4 can see "user saw form → focused name → completed name → focused phone → abandoned" vs. "user saw form → focused name → completed name → focused phone → completed phone → completed email → submitted". The `field_name` metadata is one of `name`/`phone`/`email`/`condition`/`message`.
- The 5 user-fillable fields (`name`, `phone`, `email`, `condition`, `message`) are tracked. The `consent` checkbox, `source` hidden input, and `website` honeypot are excluded from the funnel-tracker to avoid inflating the funnel with non-content interactions and to keep spam-bot keystrokes from polluting the data.
- 1 file changed (`components/forms/consultation-form.tsx`), 128 insertions(+), 1 deletion(-). No schema changes (tracking/HTML-only). No new dependencies; `IntersectionObserver` is supported in every browser we ship for and is a built-in browser API.
- `npm run build`: passes (20 routes, 0 TypeScript errors). `npm run validate:schema`: **105 blocks / 0 errors / 0 warnings** (unchanged — no schema changes). Verified the compiled JS bundle (`.next/static/chunks/01j0kwyu1elo7.js`) contains all four event names: `form_view`, `form_start`, `form_field_complete`, and `form_submit` — each exactly once. The minifier inlined the `TRACKED_FIELDS.includes(name)` check to `dg.includes(n)` on the compiled form, confirming the field-name allowlist survives the build. Verified the IntersectionObserver fallback path is in the bundle (`typeof IntersectionObserver === "undefined"`).
